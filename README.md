# Chirpy

Chirpy is a small Twitter-style social network backend written in Go. Users sign up, log in, and post short messages called **chirps**. It's a JSON REST API backed by PostgreSQL, built with only the Go standard library for routing.

## Why it's interesting

- **Standard-library HTTP server:** method-based routing (`GET /api/chirps/{chirpID}`) with Go 1.22+ `net/http`, no framework
- **Real authentication:** Argon2id password hashing, short-lived JWT access tokens, and revocable refresh tokens stored in the database
- **Authorization:** users can only edit their own account and delete their own chirps
- **Type-safe SQL:** queries are written in plain SQL and turned into Go code with [sqlc](https://sqlc.dev); schema changes are managed with [Goose](https://github.com/pressly/goose) migrations
- **Webhooks:** a payment-provider webhook (secured with an API key) upgrades users to "Chirpy Red" membership

## Requirements

- Go 1.22 or newer
- PostgreSQL 15 or newer
- [Goose](https://github.com/pressly/goose) for migrations:

```bash
go install github.com/pressly/goose/v3/cmd/goose@latest
```

## Getting started

1. Clone the repository:

```bash
git clone https://github.com/milinkovicluka/chirpy.git
cd chirpy
```

2. Create a database called `chirpy`:

```bash
sudo -u postgres psql -c "CREATE DATABASE chirpy;"
```

3. Create a `.env` file in the project root:

```
DB_URL="postgres://postgres:postgres@localhost:5432/chirpy?sslmode=disable"
PLATFORM="dev"
JWT_SECRET="replace-with-output-of-openssl-rand-base64-64"
POLKA_KEY="your-polka-api-key"
```

| Variable | Purpose |
|---|---|
| `DB_URL` | PostgreSQL connection string |
| `PLATFORM` | Set to `dev` to enable `POST /admin/reset`; any other value disables it |
| `JWT_SECRET` | Secret used to sign access tokens. Generate one with `openssl rand -base64 64` |
| `POLKA_KEY` | API key the Polka payment webhook must send |

4. Run the migrations:

```bash
cd sql/schema && goose postgres "postgres://postgres:postgres@localhost:5432/chirpy" up && cd ../..
```

5. Build and run the server:

```bash
go build -o out && ./out
```

The server listens on `http://localhost:8080`.

## API

Endpoints marked 🔒 need an `Authorization: Bearer <access token>` header.

### Users and auth

| Method | Path | Description |
|---|---|---|
| `POST` | `/api/users` | Create a user. Body: `{"email", "password"}` |
| `PUT` | `/api/users` 🔒 | Update your own email and password |
| `POST` | `/api/login` | Log in. Returns the user, an access `token` (1 hour) and a `refresh_token` (60 days) |
| `POST` | `/api/refresh` | Send `Authorization: Bearer <refresh token>` to get a new access token |
| `POST` | `/api/revoke` | Send `Authorization: Bearer <refresh token>` to revoke it |

### Chirps

| Method | Path | Description |
|---|---|---|
| `POST` | `/api/chirps` 🔒 | Post a chirp (max 140 characters). Body: `{"body"}` |
| `GET` | `/api/chirps` | List chirps. Optional query params: `author_id=<uuid>`, `sort=asc\|desc` (default `asc`) |
| `GET` | `/api/chirps/{chirpID}` | Get one chirp |
| `DELETE` | `/api/chirps/{chirpID}` 🔒 | Delete your own chirp |

### Other

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/healthz` | Readiness check, returns `OK` |
| `POST` | `/api/polka/webhooks` | Payment webhook. Needs `Authorization: ApiKey <POLKA_KEY>` |
| `GET` | `/admin/metrics` | HTML page showing how many times the site was visited |
| `POST` | `/admin/reset` | Delete all users and reset metrics (only when `PLATFORM=dev`) |
| `GET` | `/app/` | Static website |

### Example

```bash
curl -X POST localhost:8080/api/users -d '{"email":"walt@example.com","password":"secret"}'

TOKEN=$(curl -s -X POST localhost:8080/api/login \
  -d '{"email":"walt@example.com","password":"secret"}' | jq -r .token)

curl -X POST localhost:8080/api/chirps \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"body":"Hello, Chirpy!"}'

curl "localhost:8080/api/chirps?sort=desc"
```

## Development

Run the unit tests:

```bash
go test ./...
```

After changing anything in `sql/queries` or `sql/schema`, regenerate the database code:

```bash
sqlc generate
```

## Project layout

```
.
├── main.go                 # config, routes and server startup
├── handler_*.go            # HTTP handlers
├── json.go                 # JSON response helpers
├── internal/
│   ├── auth/               # password hashing, JWTs, refresh tokens, header parsing
│   └── database/           # code generated by sqlc
└── sql/
    ├── schema/             # Goose migrations
    └── queries/            # SQL queries for sqlc
```
